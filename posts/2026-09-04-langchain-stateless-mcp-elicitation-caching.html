LangChain Ships Stateless MCP Support With Elicitation and Caching

2026-09-04

LangChain moved its Model Context Protocol support out of the separate adapters package and into the core library this week, timed with the latest MCP spec revision that made stateless operation possible.

Stateless Connections Replace Session-Pinned Servers

The July 2026 MCP spec rewrite eliminated protocol-level sessions entirely. A server redeploy no longer kills live connections because there are none to kill. LangChain's new langchain.mcp module, built on FastMCP 4, takes advantage of this by negotiating protocol era per connection — trying the newest spec and falling back automatically for servers that haven't upgraded. The MultiServerMCPClient class collapses into a single MCPAdapter that handles transport, auth, and protocol negotiation. FastMCP's ClientGroup lets each server keep its own connection era and credentials, with tool names automatically prefixed to avoid collisions.

Elicitation and Caching Arrive as First-Class Features

Two capabilities that developers had been asking for shipped together. Elicitation — a tool pausing mid-call to ask the caller a question, like confirming a destructive action — now maps onto LangGraph's interrupt primitive: the run pauses, a human answers, execution resumes. On the caching side, servers can declare how long their tool catalog stays fresh, and MCPAdapter serves that catalog from an in-memory cache instead of re-fetching on every agent run. Both features depend on the stateless spec revision that removed the need to hold open a connection while waiting for a response. Auth support covers bearer tokens, full OAuth 2.1 flows, machine-to-machine credentials, and Client ID Metadata Documents — the mechanism that replaced Dynamic Client Registration in the 2026-07-28 spec revision.
